# Diseño de interfaces frontend

1. **No generes componentes antes de definir dirección de diseño y tokens** (color, tipografía, espaciado, radios, sombras, motion) cuando el proyecto lo requiera. Lee `.project/VISUAL_DIRECTION.md` si existe.
2. Cada decisión visual debe tener relación con el producto: tipografía, color, forma y motion con una razón escrita.
3. Evita como receta automática: Inter/Roboto/system-ui como display sin justificación, gradientes morado/azul, glassmorphism gratuito, tarjetas para todo, exceso de pills/badges/sombras, hero + 3 cards + CTA, blobs decorativos, layouts simétricos por defecto, copiar startups.
4. Una tendencia solo entra si mejora la experiencia o la identidad.
5. **Anti-generic check** antes de cerrar: ¿se reconoce sin el logo? ¿podría ser cualquier SaaS? ¿la tipografía/color/motion tienen razón o función? ¿hay una interacción memorable? ¿se diseñaron estados reales? ¿la estética perjudica la claridad?
